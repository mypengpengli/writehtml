# 对外交付形态 · 结果卡标准（M0 落地细则）

> 配套：`de-ai-novel`（编辑-好运专家包内嵌技能）
> 配套准则（编号对照见 `../SKILL.md`「对外交付纪律」表）：**M0 可见性总判据 / M7 不外露内部 / M12 里程碑必须有全貌 / M13 交付命名**
> 一句话：**作者要的是「哪儿有问题、怎么改」；「为什么有问题、依据是什么」是我家里的账，不进交付。**

---

## 一、总则

**最高判据（M0）**：**用户相关的一切进展必须可见，我自己的内务一律不可见。**

落到"交付结果"这一件事上，M0 的具体形态就是一张卡：

> **卡片 ＝ 进度全貌（M12）＋ 内部信息清零（M7）**

内部完整报告（判定表、语义归类、统计信号、规则反哺）**照样要做**——它是本技能的沉淀载体与工作底稿，但**不直接交付**。它是卡的**原料**，不是卡的**替代**。

**判据一句话**：这条信息是「**他这件事怎么样了**」（发），还是「**我家里怎么运转**」（不发）？

---

## 二、字段与顺序（固定，不许改序、不许省栏）

| # | 字段 | 内容 | 归属 |
|---|---|---|---|
| 1 | **范围** | 作品 / 章 / 字数 ＋ **阶段** | 对外 |
| 2 | **查出** | 一共发现多少条 | 对外 |
| 3 | **直接改** | 已经改掉多少条 | 对外 |
| 4 | **建议删** | 已经删掉多少条 | 对外 |
| 5 | **要你拍板** | 多少条要作者裁决 | 对外 |
| 6 | **待裁定明细** | 逐条：**是什么** ＋ **默认动作** | 对外 |
| 7 | **下一步** | 一句，他要做的一个动作 | 对外 |

### 三条硬要求

1. **必须标阶段**。扫描完还没动笔 → 第 3、4 栏填 **0** 并注明"尚未动笔"。
   **不许把未完成的动作写成已完成**——虚报进度比不报更违反 M0，因为 M12 要的是**真实**全貌。
2. **第 6 栏每条必须带默认动作**（"你不回我就按这个做"）。
   无默认动作的待裁定项 ＝ **阻塞项，不许出现**。呼应 M2 第三出口、M14「我先填满，他只改不同意的」。
3. **累积口径**（M12）：连载 / 多轮场景下，第 2–4 栏报**累积值**（全书到现在），不是本轮新增。
   单次任务报本次。**两个口径不许混用**，且在卡上写明是哪种。

### 降级规则（M12）

| 条件 | 形态 |
|---|---|
| 能落文件并预览 | 卡片形态（HTML / 原生组件） |
| 不能 | 字段卡文本 |

**两种形态的字段名与顺序完全一致**——降级只换壳，不换内容。

## 三、红线 · 什么不许进卡（M7 清单）

| 不许进卡 | 为什么 |
|---|---|
| 规则编号（C05 / F1-3 / 特征28 / T1-T6 / L0-L5 / 六轴） | 作者看不懂，也不需要懂 |
| 扫描器名、脚本路径、参数、指标实测值与阈值 | 我家的仪表盘 |
| 我自己的过程台账与自查记录 | 我自己的内务 |
| 轮次计数（"第 N 轮"）、版本号（`_vN` 除外——它是交付物名） | M12：进度数字只写 **N/M** |
| 文件路径、目录结构、缺哪个文件、references 清单 | M7 原文点名 |
| 依据、判例、为什么、分析过程、"回头我补上" | 只在**作者追问**时答 |

> ⚠️ **边界提醒（防走样）**：可藏的是**诊断依据**，不是**改法**。
> 作者随时有资格问"这句为什么这么改"，那一刻必须答得出来。
> **M7 不是黑箱许可证。**

## 四、内部底稿形态（作者点名索取时才给）

1. **判定表**：`| 行号 | 原句 | 命中规则 | 判定(违规/豁免/边缘) | 性质(AI味/风格差异) | 建议改法 |`
2. **对白得分**：逐段 T 类命中与得分（<2 分＝虚对白）
3. **主线核查 + F1 章内一致性结论**
4. **统计信号**：CV / Burstiness / STTR-sd（辅助非判决）
5. **教训沉淀卡**：`本轮发现 → 规则缺口 → 反哺动作 → 已写入位置`


> 六项默认**不出交付**。作者说"给我看判定表"才给——给了也只给被点名的那一项。

## 五、反面话术（逐条对照）

| ❌ 违规 | 违反 | ✅ 改成 |
|---|---|---|
| 交一份带 §编号、C 类分布的文档给作者 | M0 / M7 | 交一张卡；报告留内部 |
| "查出 34 条" 之后没写改了几条、怎么改 | M0 / M8 | 四栏齐全：查出 / 改 / 删 / 待定 |
| "有 3 条要你定" —— 不说是哪 3 条 | M12 | 逐条列出「是什么」 |
| 待裁定项没有默认动作 | M2 / M14 | 每条补"默认按……" |
| 只报本轮新增，不给累积 | M12 | 报累积值并注明口径 |
| 主动问"这稿是 AI 写的还是你自己写的" | **M0 / M7** | 不问。那是内务（只影响我的评分口径） |
| 报"校验通过／字段无洞／已记进工作日志" | M7 / M13 | 一个字都不说 |
| 一次抛多个开放题，把活推回作者 | M8 / M14 | 一次一道动作 |

## 六、交付前自检四问

1. 这张卡里，有没有任何一项是**我家里的事**？有 → 删。
2. 第 3、4 栏的数字，**是不是真做完了**？没做完 → 填 0 并标阶段。
3. 第 6 栏每一条，**作者不回复会不会卡死**？会 → 补默认动作。
4. 这次报的是**累积还是本次**？口径写了吗？

## 七、编写实录（为什么有这条）

- **2026-09-11**：本专家首次交付一部长稿的扫描结果时，交出的是一份含六轴判定、分布统计、统计信号、质量指标、规则升级清单的**内部报告**。
  作者指出：用户想知道的是"哪里有 AI 味、怎么改"，不关心"为什么有、依据是什么"；并下令**未来所有对外封装上传的专家都要执行**：用户相关的一切进展必须可见（M12），我自己的内务一律不可见（M7）。
  同轮自查出两处违规：① 公开追问"这稿是 AI 稿还是人稿"（纯内务）；② 全篇未报"已改 / 已删"两栏。
  本文件据此立标准，适用于本包全部对外交付。
