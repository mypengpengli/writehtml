# 设定锚点登记册 · 通用模板（v4.4.0 新增 · 专家包层）

> 🔒 **防污染声明**：本文件为**通用模板**，全部使用占位符【主角】【某道具】【反派甲】等。
> 任何项目专属名称/设定**严禁**写入本模板——项目实例只落在对应项目的 `项目档案/设定锚点登记册.md`。
>
> **用途**：主理人在 Phase 2.X（人物设定完成后、大纲启动前）复制本模板到项目档案，填入本项目锚点值。
> **配套**：`scripts/P0_5_delivery/check_anchors.py` 读取 `设定锚点登记册.json`，机器扫描正文一致性。

---

## 一、锚点四类

| 类别 | 覆盖内容 | 典型锚点 |
|------|---------|---------|
| 道具 | 金手指/武器/信物/关键物件的定位、归属、外观 | 佩戴手/持有者/来历 |
| 人物关系 | 亲属/师承/隶属的称谓溯源 | 谁是谁的什么 |
| 称谓 | 反派/配角全名与首次认知方式 | 名/职/首次如何被认知 |
| 修为 | 各角色境界与感知边界 | 当前境界/可感知范围 |

---

## 二、登记表结构（表格版，供人工阅读）

```
锚点ID │ 类别   │ 权威表述            │ 变体白名单        │ 禁用语
───────┼────────┼────────────────────┼──────────────────┼────────────
A001   │ 道具   │ 【主角】左手食指    │ 左手指间/左手指根 │ 右手/指尖
A002   │ 关系   │ 【某遗物】祖父转交  │ 祖父的戒指        │ 混用为"遗物"
A003   │ 称谓   │ 【反派甲】执事·全名X│ 执事/X           │ 未交代全名前直呼全名
A004   │ 修为   │ 【配角乙】跌落前X境 │ 曾是修士          │ 凡人"感知威压"
```

**字段释义**：
- **权威表述**：唯一正确写法（机器比对基准）
- **变体白名单**：允许的等价写法（命中=安全）
- **禁用语**：一票否决（命中=违规，无论语境）

## 三、JSON 版（机器可读 · 供 check_anchors.py）

```json
{
  "schema": "anchor-registry/v1",
  "project": "【项目名】",
  "anchors": [
    {
      "id": "A001",
      "category": "道具",
      "canonical": "【主角】左手食指",
      "whitelist": ["左手指间", "左手指根"],
      "forbidden": ["右手", "指尖"]
    },
    {
      "id": "A002",
      "category": "人物关系",
      "canonical": "【某遗物】祖父转交",
      "whitelist": ["祖父的戒指"],
      "forbidden": ["遗物直接归为曾祖"]
    }
  ]
}
```

> JSON 存放：项目档案/设定锚点登记册.json（与 .md 同目录同步维护）
> 脚本读取失败/缺失 → check_anchors.py 输出 SKIP（人工复核），不阻断流程。

---

## 四、维护规则

1. **新增设定即登记**：正文/推演出现新道具/新关系/新称谓 → 立即补登（否则 #17 卡判 🟡）
2. **拍板变更即更新**：用户改方向 → 走二次拍板 → 同步更新锚点册
3. **每章写作前**：主理人组装注射包时，脚本自动提取"本章涉及锚点子集"（assemble_injection_pack.py v4.4.0）
4. **每章质检时**：check_anchors.py 机器预扫 → 周言 #17 人工复核 WARN/FAIL
5. **多项目隔离**：每个项目独立锚点册，绝不跨项目读取
