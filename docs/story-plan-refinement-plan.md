## 1. 总体判断

所附 26 条建议总体有意义。当前主要问题集中在规划语义、使用路径与长篇规模下的可用性；独立 Story Plan、Pi Agent、正文编辑器和 World State 可以继续作为基础。

按用户的新要求，删除旧版作品设定分类、导入向导和相关兼容分支。旧创作数据不作为本轮设计约束，也不为它增加恢复入口或映射界面。必要的数据库结构升级自动执行，账号、登录、模型配置等正常功能不因删除旧业务而重建。

优先完成正确性，再调整页面，再连接推演与正文，最后补规模与交互验证。现有正文 CAS、World State 输入指纹及提交事务、场景身份匹配、Pi 原生能力继续保留。

## 3. 信息架构与删除范围

顶层统一为 `世界设定 / 剧情规划 / 章节状态`。

- 世界设定：人物、规则、地点、技能、道具、组织；主体展示设定资源及详情，不再以章节时间线作为默认内容。
- 剧情规划：总纲、卷/阶段、章节计划、支线/伏笔和剧情推演。
- 章节状态：正文产生的章前状态、实际场景、变化、章后状态及待确认事项，同时展示本章计划核对结果。
- 创作总则：在世界设定页提供独立入口，保存基调、叙事视角、文风与作者禁忌。它是作者要求，不属于故事世界事实，不计入人物或规则数量。

删除 `legacyNotesBanner`、`classifyLegacyNotes()`、`/notes/classify`、`import_work_notes_to_story_plan()`、`legacy-work-notes` 导入分支，以及运行时对 `notes_role` 的依赖。

原作品设定入口改名“创作总则”，去掉人物、世界观、大纲的混合示例。底层可直接复用 `works.notes`，无需为了重命名重建整套数据表。旧混合内容不自动转成创作总则；废弃的数据可在这次升级中清理，前端不提供迁移向导。

同步检查 `context_builder.py`、`main.py` 的旧聊天路径与 `llm.py` 的写作提示，避免界面改名后仍把创作总则当“人物/世界观/大纲”发送。创作总则进入写作、润色和规划提示；World State 的事实分析输入排除它。

## 4. 规划与正文实现分离

### 4.1 数据职责

`story_plan_nodes.status` 只保留：

| 内部值 | 界面用语 | 操作 |
|---|---|---|
| planned | 规划中 | 确定采用 |
| committed | 已确定 | 改回规划中 |
| abandoned | 已放弃 | 从废案恢复 |

`story_plan_realizations.status` 独立保留 `pending / partial / realized / deviated`。记录正文实现时不再修改计划生命周期。

增加统一的实现结果解析函数，供列表、详情、章节状态、上下文和统计共同使用，禁止各处使用 `find(source_current)` 各自猜测：

- 只采用与当前正文和有效计划内容一致的核对记录。
- 按查看章节时点筛选，不让第 30 章完成的事件影响第 5 章的状态判断。
- 同一章节采用最新有效核对；跨章计划展示截至所选时点的进展及来源，不从单个子章节的完成推断整卷完成。
- 没有记录：待核对；只有过期记录：正文或计划已改，待重新核对。
- 过期不等于“确认未完成”，但旧记录不能继续作为排除该计划的依据。

续写上下文不再把当前有效完成的事项列为待实现任务；本章改写或用户明确要求核对原计划时，仍可读取其作为原设计参考。所有计划继续保持“作者意图”的标签。

### 4.2 版本与失效

保留现有 `revision` 作为编辑并发保护。先规范化比较关联列表，重复提交相同内容不产生版本、不使 realization 失效。

将“编辑版本”与“核对依据”区别处理：采用确定性的 `plan_content_hash` 标识需要正文证明的计划内容。实现记录保留原 `plan_revision` 用于追溯，同时绑定这一内容指纹。标题、目标、摘要、冲突、预期结果、详细计划或章节绑定改变时需要重新核对；仅移动显示顺序、调整上下文发送策略或 planned/committed 切换，不让已验证正文凭空失效。跨父级移动、范围变化等影响核对范围的操作保守地要求重核对。

正文删除、正文版本变化、相关章序调整继续经过现有失效入口处理，不另做第二套正文保存机制。

### 4.3 证据和并发

- Agent 写入 partial、realized、deviated 时，要求非空原文证据，并在数据库提交事务内核对证据、计划版本和正文版本。
- 读取工具提供修订号，核对工具传回它实际分析过的版本；发生变化时返回“资料已变，请重新核对”，不能给旧判断贴上新版本号。
- `source` 由手工 API 或 Agent 服务端入口确定，不允许模型通过填写 manual 绕过证据校验。
- 作者可手工确认完成或偏离，无原文引用时明确显示“作者确认”。
- “应发生的事件完全没有出现”很难用一句引文证明。AI 缺少可核验片段时记录“待核对 + 疑似未覆盖原因”，由作者裁定，不捏造证据。

## 5. 上下文策略

普通表单显示“写作时参考”，高级选项收起。高级设置保留四种策略：

| 策略 | 普通显示 | 行为 |
|---|---|---|
| auto | 系统自动选择 | 本章、上级方向和少量近期衔接 |
| planning_only | 只在规划/推演时使用 | 普通写作不自动发送 |
| writing_range | 仅指定章节范围 | 写作时严格按范围过滤 |
| never | 不自动发送给 AI | 自动上下文和推演都排除 |

取消“写作时参考”对应 planning_only，含义是停止普通写作自动引用，不删除计划，也不取消规划时使用。高级设置显示真实策略；重新开启时恢复有效的原指定范围，否则使用 auto。用户明确点击“交给 AI”是单独的一次引用操作，目标条会显示本轮实际发送对象。

`writing_range` 至少有一个端点；两端都存在时按章节 ord 校验起点不晚于终点；端点必须属于当前作品且未删除。章节排序或删除造成范围失效时显示待修正，并停止范围自动引用，不把缺失端点解释为无限范围。

选择顺序统一为：任务类型与废案过滤 → 策略/范围硬条件 → 对当前章节的关联程度 → 本时点实现结果 → 上下文预算。不能先命中直接计划，再绕过作者的范围设置。

planned 的模型文字使用“作者规划，可调整”；committed 使用“作者已确定计划，尚未发生，除非本轮明确要求修改否则应遵循”。同等关联程度下优先 committed，不因此加载所有远期已确定计划。

压缩方向采用 `context_summary → summary → goal` 的单一回退；不重复拼三份摘要。自动裁剪长度无法判断剧透，新建总纲建议默认“只在规划/推演时使用”，作者主动开启写作参考后再发送压缩方向。详情中的上下文预览列出实际发送文字及原因，不宣称截断就能避免泄露结局。

规划与推演也优先加载当前节点、上级和相关范围；全书检查由明确任务请求扩展，不在每次局部推演时全量灌入所有章节计划。

## 6. 页面及交互

### 6.1 主要布局

- 大屏：左侧可折叠结构导航，中部路线/内容区，选中对象后打开详情，AI 助手继续位于最右侧并共用现有会话。
- 布局按工作区剩余宽度决定详情是并排还是抽屉，不能只按整个窗口宽度判断。建议导航 240–260px、详情 340–380px、中部最低约 480px；空间不足先收起导航，再让详情覆盖工作区内一部分。
- 手机：默认显示主内容；导航、详情按需打开，同一时刻只显示一个前景抽屉。AI 可随时打开，关闭后回到原节点和滚动位置。
- 保留浅色工作区底色，编辑输入使用清晰边框和不同表面色；不新增大块装饰面板。
- 保存状态始终可见，未同步、保存失败、待重新核对各用准确文字，不能仅依靠颜色。

### 6.2 路线为默认视图

提供 `路线 / 卡片` 两种模式。路线以可折叠结构清单展示总纲、卷/阶段、章节和场景；不引入另一个自由拖拽画布框架。

支线/伏笔依附所挂靠的卷或章节显示，可展开查看。场景主要出现在章节内部，不新增全书“场景”页。卡片模式保留现有能力，但按选中范围和筛选展示，不默认绘制几百个场景。

左侧支持搜索标题、摘要、目标、冲突、预期结果、详情；搜索结果保留祖先路径。提供“定位当前章节”，展开祖先、滚动并高亮；一章有多条计划时列出匹配项，不任意认定其中一条是唯一主计划。

默认隐藏废案，独立“废案”入口查看和恢复。版本历史留在单条计划详情，避免和废案混成同一个历史概念。放弃带子节点的规划时，默认针对整个分支并在确认中显示数量，记录原生命周期以便恢复，不让仍活动的子计划从树中消失。

### 6.3 详情表单

常用区：标题、摘要、写作目标、核心冲突、预期结果、详细计划，以及章节类型的章节绑定。字段可为空，不要求作者逐项填满。

状态显示为徽标，通过“确定采用 / 改回规划中”动作更改。“放弃此规划”放在更多菜单并保留确认。完成情况为独立的核对结果，不能在生命周期下拉框里选“已完成”。

更多设置：类型、上级结构、上下文高级策略、范围、上下文摘要、关联设定和版本历史。context_summary 为可选项，不要求重复填写。

关联设定改为“已选标签 + 搜索结果”，搜索结果按人物、地点、规则等分组，支持键盘选择与删除。无需新增搜索服务，先用已加载的设定数据检索。

高频动作：`打开正文 / 创建对应章节`、`从这里推演`、`交给 AI`。只有章节计划显示“创建对应章节”；场景计划前往其所属章节；卷或总纲不因一次点击生成同名正文章节。

### 6.4 选择、定位与 AI 目标

查看对象只改变浏览与编辑状态。点击“交给 AI”才设置本轮目标，并打开/突出 AI 区的目标条，可明确取消。选择另一张卡片不改变已经引用的目标。

AI 目标记录对象 ID 与来源时点；发送前刷新最新已保存内容，避免作者改完卡片后仍发送先前复制的旧文字。切换作品时清除不属于当前作品的目标。普通选择与目标状态使用不同视觉标记。

世界设定隐藏原章节选择器。剧情规划使用“定位章节”，保存独立的浏览定位状态，不修改编辑器的 currentChapterId。章节状态保留真正的时点选择器。只有“打开正文”才明确切换编辑章节和相应会话。

### 6.5 新建与排序

无总纲时默认新建总纲；已有总纲时“新建”提供类型菜单。子计划默认按 总纲→卷/阶段→章节→场景 创建，支线/伏笔可挂靠相应节点。

章节计划优先关联明确选中的定位章节；没有定位时使用当前编辑章节。存在计划时提供打开已有计划的入口，也允许作者明确创建同章的另一条计划。

上级选择推荐合理结构；后台保持同作品、无自引用、无循环等硬约束。允许作者直接从卷或章节开始规划，不强制补齐总纲。

排序第一版使用上移/下移图标及键盘可访问按钮，同父级内原子调整 ord，并校验相关节点修订号。它只调整规划顺序，不自动重排真实章节；已有正文的实际章序继续由编辑器管理。跨父级移动通过上级设置进行。

## 7. 推演、采纳、正文形成连续操作

“从这里推演”创建或定位与该计划关联的沙盘起点，保留计划 ID、版本、上级路径及明确的故事时点。

具体流程：

1. 保存当前表单并打开关联沙盘，不在打开页面时自动调用模型。
2. 用户点生成后加载当前计划、祖先方向、有效规则和人物状态、所选分支路径。
3. 对已绑定章节的待写计划，默认从该章之前的已确认状态推演；从写完章节继续时可明确选择章后状态。未绑定计划提供起始时点选择，不自动使用全书最后一章。
4. 推演中的路径标为“该分支假设”，不能当作已经写入正文的事实。
5. 采纳默认进入正式规划；采用最近的已关联祖先作为 parent，必要时可选择其他位置。
6. 重复采纳同一候选返回原计划，不覆盖作者后续修改，不把 committed 改回 planned。只有“更新已关联规划”才执行覆盖且使用 CAS。
7. “规划并新建章节”及“创建对应章节”通过同一个原子、幂等服务完成绑定，双击和重试不会创建多个章节。

新增操作复用现有沙盘和数据库，不另造推演引擎。采纳过程中创建计划、绑定章节、写回沙盘关联应在同一事务内完成。若沙盘允许多入边，显式使用当前推演路径确定上级，不任意取数组中的第一条边。

## 8. 本章计划与实际结果

章节状态页顶部新增简洁的“本章计划”区域；多条计划逐条显示目标、预期结果和有效核对状态。提供查看计划、查看证据、核对计划和作者确认。

下方继续现有章前状态、场景、变化、章后状态。实际结果来自正文和已确认 World State；规划不会被写进 World State 输入或混成规则。

核对由作者按钮或 AI 的实现核对工具触发。查看页面、切章节、保存表单、显示统计都不自动产生新模型请求。核对显示它采用的正文时点；旧证据可以查看历史，但不能当成当前有效证据高亮。

三个页签顶部各一条可点击的状态统计：

- 世界设定：人物、规则、地点、待确认，点击按类别筛选。
- 剧情规划：卷/阶段、已关联计划的章节数/实际章节数、待完成支线伏笔、有效偏离记录数。
- 章节状态：查看章节、分析是否同步、待确认数、计划待核对或部分实现等。

统计来自数据库，不由 AI 打分。章节覆盖率按不同 chapter_id 去重，不把同章多个计划累计成多章；过期偏离不计入当前偏离数。没有计划或缺少核对时显示对应状态，不伪装成“全部健康”。

## 9. 性能与自动保存

`list_story_plan_nodes()` 改为节点、关联、实现记录三类批量查询，另外允许固定数量的权限检查查询。通过 work_id JOIN 获取关联，避免每节点查询或构造超大 IN 参数列表。详情 API 可继续按单个节点读取。

前端每次加载构造 `nodesById`、`childrenByParent`、`plansByChapter`，路线和搜索复用索引。树可折叠，只渲染展开分支；本轮不预先引入虚拟列表或图布局依赖。

自动保存继续本地草稿 + 延迟服务器保存 + CAS，补齐以下边界：

- 切节点、开新节点、看版本、从计划进入推演前，处理原对象的待保存任务。
- 每个保存任务绑定作品、对象 ID、提交内容及基础修订号；旧响应不覆盖新选中对象的表单。
- 草稿带基础修订号及明确空值，恢复时能真正清空原有上级、范围或关联，不把 null 跳过。
- 同内容和同关联集合为 no-op，不新增版本。
- 失败保留草稿并显示未同步；不能因为抽屉关闭而丢掉错误和重试入口。
- 不在后台保存完成后重绘当前输入表单，避免输入焦点、光标或滚动位置跳动。

## 10. 文件与接口边界

| 位置 | 主要工作 |
|---|---|
| `db.py` | 删除运行时兼容分支；拆分状态；内容指纹与统一实现结果；范围校验；批量读取；排序及创建绑定事务 |
| `context_builder.py` | 创作总则语义；范围优先过滤；planned/committed 模型文字；按时点读取实现结果；摘要单一回退 |
| `main.py` | 删除分类 API；统一 HTTP/Agent 错误判断；证据和版本校验；推演起点、采纳层级及幂等服务；统计与章节计划数据 |
| `llm.py` | 统一旧写作入口中的创作总则用语及来源，不改模型参数和调用机制 |
| `static/index.html` | 三个顶层入口、路线模式、分组表单、定位控件、显式 AI 目标动作 |
| `static/app.js` | 分离浏览章节/编辑章节/AI 目标；树索引与搜索；保存任务边界；新建、排序、推演及采纳 |
| `static/style.css` | 路线结构、编辑表面色、响应式详情抽屉、窄屏操作及焦点可见性 |
| `test_smoke.py` 等 | 覆盖以下验收场景，保留现有完整性测试 |
| `README.md` | 移除旧兼容用法，说明新操作与核对成本 |

新增接口以必要的用户动作为单位：同父级排序、创建并绑定章节、从计划创建推演起点、章节计划核对。沿用已有认证和权限检查，不增加第二套 API 风格。界面和 Agent 调用同一批业务函数，避免只修 HTTP 而遗漏工具路径。

不改 Pi 内核，不增加工具次数限制；不重写 World State 请求、缓存和事务；不引入新的服务或修改 Docker 部署拓扑。

## 11. 验收清单

### 正确性

1. planned/committed 均按章节范围进入写作上下文，两者发给模型的语气和优先级不同。
2. 有效 realized 不再作为待实现任务发送；正文或计划内容修改后显示待重新核对，并重新参与相关计划选择。
3. 第 30 章的实现记录不改变第 5 章时点的完成状态。
4. 同一计划跨章、多条同章计划、卷与子计划的完成判断不相互误覆盖。
5. Agent 空证据、正文中不存在的证据、分析后正文/计划版本变化均拒绝落库；作者确认可无引文。
6. writing_range 缺少端点、倒序、跨作品、删除端点均明确处理；直接计划和祖先不能绕过范围。
7. 同内容重复保存不新增版本，不失效实现记录；纯显示排序不清除有效完成结论。
8. Agent 保存非空 conflict 字段成功，真正 CAS 冲突仍返回错误。
9. 沙盘子候选采纳落入正确父级；重复采纳不覆盖正式计划；双击创建章节只产生一章。
10. 同父级排序、放弃分支及恢复保持结构完整，无跨作品引用或循环。
11. 正文删除、恢复及排序后的实现记录失效行为一致。
12. World State 输入完全没有 Story Plan 和创作总则；规则、角色事实与已有输入指纹校验仍通过。

### 交互及规模

13. 查看对象不更换 AI 目标；“交给 AI”明确显示引用对象，发送使用最新已保存内容。
14. 规划章节定位不修改正文 currentChapterId、编辑器草稿或当前会话。
15. 默认不显示废案；废案页面能恢复并返回原路径。
16. 搜索能命中详情与冲突文字，定位展开祖先；关联设定可搜索添加删除。
17. 连续输入后立刻切节点、断网、刷新、双标签页冲突、打开版本均不丢草稿或错误覆盖。
18. 使用 300 条及 1000 条计划验证查询数不随节点数线性增长，返回关联顺序和 API 数据结构一致。
19. 390px 手机、约 1024px 中屏、1440px/1920px 桌面，验证 AI、导航、详情同时使用时的边界、滚动和可点击性。
20. 打开页面、切页签、查看状态条、自动保存均不触发模型请求。

实施完成后运行 `.github/workflows/ci.yml` 的现有语法检查及 `test_web_search.py`、`test_smoke.py`、`test_pi_runtime.py`；以真实浏览器验证抽屉、保存和定位流程，不能只测静态截图。
