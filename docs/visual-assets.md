# Word 图文资料、衍生图库与素材交接

## 导入与归档

先选择作品，在 AI 输入框回形针上传 `.docx`。文档原文按正文段落与表格的实际顺序提取；图片以稳定编号嵌入原文索引，保存图注、附近标题与段落。页眉、页脚等无法定位到正文的图片也会提取，但明确标注未定位，不猜测归属。PNG、JPEG、WebP、GIF、AVIF 可以保存，损坏或不支持的格式会列出警告；不读取外链图片，也不执行文档内容。

与普通本轮文字附件不同，带 `document_id` 的 Word 原文和图片存入当前作品数据库与持久图片目录，但不会自动变成正式设定或正文。「AI 归档」会明确授权同一个 Pi 助手整理本份资料，内置 `document-visual-import` Skill 也可手动选择。作者可用自然语言限定只导入人物、只处理图片或只复制章节。

未来大纲归入 Story Plan，不当作世界事实。已写正文按标准章节标题给出索引，`import_document_chapter` 直接复制提取后的原文，不通过模型重写、不覆盖已有章节；同一个文档的同一章节重试不会重复创建。已导入章节在回收站时要求先恢复或彻底删除，不悄悄生成副本。无法自动识别章节标题时仍可由 AI 使用原有章节工具处理，覆盖已有正文前必须核对作者指令。

## 图片归属与衍生

图片归属采用明确的 `target_type` 与 `target_id`：人物是 `character`，地点、建筑、场地、道具、组织标识等是相应 `card`。显示名称可以修改，关联不会依赖同名字符串。

每张图独立保存：名称、说明、衍生类型、可选原图 ID、可选章节 ID、是否主图，以及导入文档和图片序号。服装、形态、状态、损毁、季节、标识等都属于同一个对象的不同视觉版本，不覆盖基础设定。原图与衍生图必须属于同一对象，不能形成循环；删除原图时保留衍生图并解除原图引用。

新导入图片默认不替换已有主图。图片需要用于多个对象时复制为独立素材后再绑定，不能悄悄更换旧归属。归属不清楚的图留在待归类图库。看图工具只按需发送缩略预览，不把图片 Base64 写进聊天历史；需要支持视觉输入的模型，纯文本模型不能假装识别了图像。

左侧资源树按「分类 → 对象 → 图片版本」展开，图片名称也能搜索。点击图片直接在原有右侧详情预览和编辑，不弹出另一套管理页面。对象详情的「图片」页签常驻上传与生成；选中图片后可重新生成或选为主图，复制和删除收进更多菜单。待归类图片和全书图库保留在画布设置及 Word 附件入口，用于批量归档。

人物、地点、建筑、场地、道具和组织等共用基础设置里的生图服务。生成与重新生成先保存候选图并展示预览，作者确认后才选为主图；取消选用也保留候选，旧图不删除。重新生成记录原图 ID，但当前调用的是文生图接口，不承诺像素级图生图或自动保持原图外观。人物原有生图与历史图库通过兼容镜像共用同一图片文件，不复制旧图片。图片信息使用显式保存，关闭或切换前提醒未保存修改。

## 导出协议

画布顶栏下载按钮或图库下载按钮生成 ZIP。正文和当前设定先完成已有同步，未确认的本章状态草稿不会被伪装成已保存事实。

- `manifest.json`：唯一关联索引，格式标识 `writehtml-creative-package`，版本 `1`。
- `prose/chapter-<id>.md`：已写正文，章节顺序、标题与 ID 在 `chapter_order`。
- `sources/document-<id>.txt`：提取的来源原文，仅作参考资料，不自动成为正式设定。
- `images/<category>/<target-type>-<id>/image-<id>.<ext>`：原始图片；未绑定图片放在 `unclassified`。
- `characters`、`cards`、`story_plans`、`scenes`、`state_versions`：结构化作品资料与状态记录。

每张图包含 `ref`、`target_ref`、`parent_image_ref`、`chapter_ref`、`chapter_status`、`document_ref`、原文件路径和 SHA-256。ID 使用类型前缀，`character:12` 不等于 `card:12`。不要根据文件名、相似图片或列表位置重新猜测归属。

Story Plan 明确标为作者未来计划，不是既成剧情。图片是视觉参考，不自动产生事实；主图也不意味着适用于所有历史章节。归档卡片保留 `status=archived` 以解释来源，不作为当前有效设定；删除或缺失的章节关联明确标为 `deleted` / `missing`，不改指向另一章。模型或下游服务仍需遵循这些语义，导出包不能控制第三方智能体的行为。

数据库元数据在同一个读取事务内取快照，图片文件不可变。读取原文件失败时拒绝输出不完整 ZIP。文件内容及路径只在验证账号和作品归属后返回；图片与原文随作品删除清理。部署仍使用现有 `/data` 持久卷与原来的 Docker 更新命令，无新增服务。

## 验证

`test_visual_assets.py` 覆盖 Word 顺序、重复导入、账号和作品隔离、人物/地点/道具/组织绑定、主图兼容、衍生原图与循环拒绝、章节原文复制、归档与删除时点、ZIP 索引与文件 SHA-256。`test_pi_runtime.py` 验证实际 Pi 图片工具内容传到兼容模型，但不存入聊天历史。`test_workspace_ui.py` 覆盖附件查看、手工绑定、衍生图、图片页签、ZIP 下载及桌面和手机布局。测试不调用外部真实模型。
