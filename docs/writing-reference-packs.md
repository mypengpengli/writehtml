# 写作方法包接入说明

来源为用户提供的 `de-ai-novel.zip` 与 `.codebuddy-plugin.zip`。源文件 SHA-256、参考文档映射见 `writing-packs-manifest.json`。ZIP 原件和解压研究副本保留在本地，不随 Git 或 Docker 构建上下文发布。

## 接入结果

新增 10 个按需 Skill，原有写作导演仍是唯一默认自动启用的工作流能力。

| 能力 | 包名 | 应用中的落点 |
| --- | --- | --- |
| 修订、去模板感 | de-ai-novel | 扫描候选、语境复核、原有正文编辑与版本 |
| 专家调度、30 个技法模块 | novel-workshop | 按任务加载专业方法和资料 |
| 世界观设计 | workshop-world-architect | 设定卡、规则、知识边界 |
| 人物设计 | workshop-character-designer | 基础人物卡、关系和动态状态 |
| 大纲规划 | workshop-outline-planner | Story Plan |
| 剧情推演 | workshop-plot-engine | Sandbox 候选与采纳 |
| 正文写作 | workshop-writing-executor | 章节编辑和多章写作 |
| 质检编辑 | workshop-quality-editor | 有证据的文学与事实复核 |
| 读者与市场 | workshop-business-analyst | 读者定位、书名简介和按需搜索 |
| 证据复核 | workshop-audit-officer | 核实实际正文、状态与工具结果 |

以上是同一个 Pi Agent 可选的专业视角，不是多个独立模型并发审稿。主理人的调度方法通过工坊与已有写作导演复用，不新建第二套状态机。

保留了 71 份来源参考：修订方法 10 份、工坊共享资料 53 份、八类专家方法 8 份。共享资料包括完整 30 个技法模块、模板、常识、写作方法及原工作流参考；它们不会整包放进每轮上下文。参考文档标注了来源与适配边界。

## 使用入口

- 右侧 AI 助手的 Skill 按钮打开「写作技能与专家」，搜索并选择；也可以直接说“从人物设计角度完善这张卡”或“帮我去掉模板感”，由 Agent 按目录激活。
- 列表的书本按钮可查看技能说明与参考资料；长文可以继续翻页或搜索。
- 正文「⋯ → 文字检查」检查整章；正文选区工具条的眼睛按钮只检查选区。
- 检查结果的「交给 AI 复核」把候选和要求放到输入框，作者发送后才调用模型；本地检查不收费、不改变正文。

## 原生工具

`scan_writing_text` 支持最新章节全文或显式文本、`all/style/consistency`、选区标记和结果分页。扫描覆盖整段输入，分页只影响结果条数。每条候选带原文字符位置、行号、证据和建议；整章结果绑定正文修订号。它借鉴源包的词面扫描和活人感检查，但没有复制源脚本的全套规则。

当前覆盖情绪定性、惯用反应、解释型对举、旁白总结、抽象氛围、邻近重复、连续同类句首、交付杂质，以及局部数量/状态变化候选。对白用保留原始位置的遮罩排除，明确状态转换不作为状态冲突。返回句长均值和标准差作为描述，不输出“AI 概率”。语义豁免、人物动机、跨章一致性、主线增量和文学质量由 AI 根据参考方法与作品事实复核。

`list_skill_resources` 列出已激活 Skill 的参考文件，`read_skill_resource` 支持 `offset/limit/query`，可读取原先被 6000 字截断的后续内容。所有资源按账号隔离；只在作品会话、未选择章节时也能发现和激活该作品的专用 Skill。读取的正文只进入当前模型上下文，不写进对话历史。

动态激活的规则和读取的资料在本次完整任务的后续工具循环中持续生效，相同资料不重复注入；下一次用户回合重新按需加载。扫描本身不调用模型；交给 AI 阅读资料、复核或改稿仍正常消耗模型 token。

本地 CLI 同样可用：

```bash
python -m writing_checks chapter.txt --profile all
python -m writing_checks excerpt.txt --excerpt --offset 40
```

## 适配取舍

来源插件的 TeamCreate、SendMessage、maxTurns、模型分级、强制退稿、固定平台阈值、文件记忆库和维护脚本没有接入运行时。规则和技法作为参考，作者的题材、文风与明确要求优先；世界事实、未来计划、候选路线继续分开保存。技能不自行修改共享资料或跨作品积累项目规则。

常识和市场资料保留了来源的历史示例；Agent 需要实时结论时必须另行检索，不能把旧示例当作最新政策、榜单或收益事实。

没有增加外部服务、第三方 Python 依赖或部署步骤。应用启动时按原有内置 Skill 同步机制安装到已有账号和新账号，保留 Skill ID。维护者有两个原 ZIP 时，可以运行 `python scripts/import_writing_reference_packs.py` 重建来源参考；这一步不在应用启动时执行。

## 验证

`test_writing_packs.py` 覆盖账号隔离、作品作用域、内置同步、长资料完整分页、检查位置、无副作用和长章节扫描；已加入 CI。`test_pi_runtime.py` 通过本地模拟模型驱动真实 Pi 工具链，验证激活、资料读取、检查及上下文生命周期，不代表对特定中转站模型的生成质量评测。

本地测试服务启动后，可运行 `python test_writing_packs_ui.py http://127.0.0.1:9138`（测试账号为 admin / UiTestPass123!，使用独立测试数据库）。测试需要 Playwright 和 Chrome，覆盖桌面、平板、手机视口、资料翻页搜索、保存最新正文后扫描和等待用户发送的复核交接；原有 `test_story_plan_ui.py` 同样保留。
